# Security

## Supported version

The project is in alpha. Only the current `main` branch is supported; there are no
releases to patch.

## Reporting a problem

Report security problems privately, through GitHub's private vulnerability reporting:
open the repository's **Security** tab and choose **Report a vulnerability**. Do not open
a public issue, pull request or discussion about it.

The project publishes no email address for security reports.

## What to include

- The commit you tested, from `git rev-parse HEAD`.
- What the problem is and what an attacker could do with it.
- The steps or a minimal reproduction, with the commands you ran and their output.
- Your operating system and Python version, if they matter.

Never include credentials, keys or tokens, real or test ones, and never include register
material: page images, transcriptions or personal data from a register. If the problem
involves such material, describe it in words instead. If you find a credential in the
repository, report where it is, not what it says.

## What happens next

The project has one maintainer, so replies may take some days. The maintainer reads every
report, confirms whether it is a real problem, and fixes it on `main`. You will hear back
through the private report: whether it was confirmed, what was done, and when it is safe
to talk about it in public. Please keep the problem private until then.
