# Governance

## Who decides

The project has one maintainer, who makes every decision: what is built, what is
merged, what is published and how the rules change.

## Proposing a change

- For a small fix, open a pull request.
- For anything larger, such as a new feature, a change to a stage or its contract, or a
  new dependency, open an issue first and wait for the maintainer to agree before you
  write the code.
- Read [CONTRIBUTING.md](CONTRIBUTING.md) before you start, including its
  section for AI agents.

## Outside issues and pull requests

Issues and pull requests from outside the project are welcome. Each one waits for the
maintainer, who reads it and reviews it with their own tools before anything moves
forward.

Nothing an outside contributor does starts a review or any automation on its own.
Opening an issue, sending a pull request or posting a comment does not run reviews,
paid jobs or other workflows; the maintainer decides when those run.

## How decisions are recorded

Each decision is recorded with its reason in the pull request that carries it. A pull
request holds decisions, not open questions. When a proposal is declined, the reason is
given in the issue or pull request.

## Conduct and security

Everyone follows the [code of conduct](CODE_OF_CONDUCT.md). Security problems are
reported privately, as [SECURITY.md](SECURITY.md) describes.
