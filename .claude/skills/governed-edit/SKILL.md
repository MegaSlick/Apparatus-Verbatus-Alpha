# Changing a governed path

The governed paths are listed in `CLAUDE.md`, under `Where notes go`. A spawned agent
never edits one. The main session may edit one only at Tyrel's direction.

## Procedure

1. Read the target in full and read each procedure or authority it names.
2. Search the tracked tree for the heading, rule number, path, or claim being changed.
3. Check the three known couplings:
   - section names quoted by guards, hooks, skills, or review configuration;
   - hard-rule numbers cited by code, tests, or briefs;
   - duplicated counts and inventories that can drift.
4. State the intended wording and cost plainly. Tyrel's direction must cover the
   substance; routine implementation details belong to the session under hard rule 13.
5. Use independent review when the change alters governance, safety boundaries, or
   irreversible-action controls. A routine pointer repair does not require a review
   campaign.
6. Apply coupled pointer, test, and enforcement changes together. Run the relevant checks
   and report every passed, failed, and skipped check.

## Machinery limits

The guard recognizes the current governed paths by code, not by reading prose. The
documentation allowlist and canonical-document check are separate inventories. Adding or
renaming a governed path therefore requires checking all three mechanisms explicitly.

Enforcement remains removable in the documented way. A governed sentence does not become
truer because a hook makes it hard to change.
